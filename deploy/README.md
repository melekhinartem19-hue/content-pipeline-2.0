# `deploy/` — установка на VPS клиента и передача продукта

Здесь всё, что нужно, чтобы поднять контент-конвейер на сервере клиента **один раз** и передать
ему готовую систему. Порядок файлов = порядок работ:

| Шаг | Файл | Что там |
|---|---|---|
| 1 | [vps-setup.md](vps-setup.md) | сервер с нуля: Node, браузер, шрифты, код, `.env`, первый запуск |
| 2 | [systemd/](systemd/) · [nginx/](nginx/) | автозапуск диспетчера и раздача публичной статики |
| 3 | [telegram-transfer.md](telegram-transfer.md) | передача 6 ботов, форум-группы и канала клиенту |
| 4 | [go-live.md](go-live.md) | приёмка: что проверяется только на аккаунтах клиента |
| 5 | [handover.md](handover.md) | эксплуатация: логи, бэкап, обновление, что делать при сбоях |

> Устройство системы и правила, которые нарушать нельзя, — в [../CLAUDE.md](../CLAUDE.md).
> Спецификации модулей — в [../specs/](../specs/).

## Что где живёт (двухмозговая архитектура)

```
┌──────────────── VPS клиента (always-on) ─────────────────┐
│  Node-диспетчер + 6 Telegram-ботов + SQLite + Nginx      │
│  тренды · тексты · картинки · PDF · согласование ·        │
│  публикация в TG/IG/Threads · воронка ManyChat            │
└───────────────────────▲──────────────────────────────────┘
                        │ готовый лёгкий Reels → очередь согласования
┌──────────── Ноут клиента (по требованию) ────────────────┐
│  Локальный Claude Code + видео-скиллы: монтаж клипов      │
│  НЕ входит в этот деплой — ставится отдельно              │
└──────────────────────────────────────────────────────────┘
```

**Видео-пайплайн (T15) в VPS-деплой не входит.** Сырое видео не проходит через Telegram-бота
(лимит Bot API — 20 МБ), поэтому монтаж локальный, на машине клиента, и ставится отдельной
инструкцией — [../video/README.md](../video/README.md). Не обещать клиенту «видео тоже будет на
сервере». На стороне VPS от видео живёт только приём готового ролика (`npm run ingest:video`) и
очередь заявок на монтаж (`npm run video:jobs`) — их ноутбук дёргает сам по SSH.

## Что должно быть у клиента ДО установки

Всё — на его аккаунтах и его оплате: мы настраиваем, но не платёжный посредник (правило 7
`CLAUDE.md`).

| Что | Зачем | Без этого |
|---|---|---|
| **VPS** (Debian 12 / Ubuntu 22.04+, 2 ГБ RAM) | там живёт вся система | ничего не ставится |
| **Домен + HTTPS** на статику | IG качает картинки по ссылке сам; по этим же ссылкам воронка отдаёт PDF | IG-карусель не опубликуется, воронка не отдаст PDF |
| **Подписка Claude Pro** и логин `claude` **на самом VPS** | весь интеллект идёт подпроцессом `claude -p` | не работает ни один агент |
| **6 бот-токенов** + форум-группа + канал | интерфейс системы | боты не поднимутся |
| ещё 2 бот-токена — Видео и Аналитик (необязательно) | заявки на монтаж и отчётность (Фаза 5) | конвейер работает, но без топика Видео и «/отчёт» |
| **Apify**: токен | сбор трендов | `/тренды` не соберёт |
| **Meta**: приложение IG + отдельное приложение Threads | публикация в его аккаунты (dev-mode) | публикация только в TG |
| **ManyChat Pro** + подключённый Instagram | воронка: 3 ключа → 3 PDF | ссылки вставляются во флоу руками |
| Контент для `brand-brain/` | голос бренда | тексты выйдут обезличенными |

Полный список переменных — в [../dispatcher/.env.example](../dispatcher/.env.example): он и есть
чек-лист «что спросить у клиента».

## Порядок в день установки

1. [vps-setup.md](vps-setup.md) — поднять сервер и убедиться, что боты отвечают в топиках.
2. [nginx/](nginx/) — статика по HTTPS, проверить, что PDF открывается по ссылке.
3. [systemd/](systemd/) — автозапуск и рестарт после перезагрузки.
4. [telegram-transfer.md](telegram-transfer.md) — **у передачи ботов и группы есть 7-дневный
   таймер**, читать заранее, а не в день встречи.
5. [go-live.md](go-live.md) — пройти приёмку по площадкам.
6. [handover.md](handover.md) — показать клиенту эксплуатацию и отдать доступы.
