# Go-live: приёмка на аккаунтах клиента

Всё, что ниже, **невозможно проверить у исполнителя**: нужны токены, приложения и подписки
клиента. До этого момента система проверена только оффлайн (`npm run smoke`, 24 проверки) и на
тестовом Telegram-стенде.

Идти сверху вниз: каждый следующий блок опирается на предыдущий. Отмечать галочки прямо здесь —
этот файл остаётся у клиента как протокол приёмки.

**Что стоит денег:** прогон `/тренды` (платный прогон актора Apify) и публикации в реальные
аккаунты. Всё остальное бесплатно. Репетиция публикации без последствий — `PUBLISH_DRY_RUN=1`.

---

## 0. Основание

- [ ] `systemctl status content-pipeline` — active (running)
- [ ] `sudo -u pipeline bash -lc 'claude -p "ответь одним словом: ок"'` — отвечает
      *(если нет — не работает ни один агент; см. vps-setup, шаг 5)*
- [ ] `npm run smoke` в `dispatcher/` — 24 из 24 зелёных
- [ ] Все шесть ботов отвечают в своих топиках, чужие топики игнорируют
- [ ] `/статус` в топике Продюсера отвечает из базы

## 1. Telegram: полный круг согласования

Это ядро продукта — оно должно пройти целиком.

- [ ] Задача в топик Сценариста → пришёл готовый текст
- [ ] Карточка появилась в топике Издателя с кнопками
- [ ] «Правка» реплаем → пришла новая версия
- [ ] «Одобрить» → **пост появился в канале клиента**
- [ ] `/очередь` у Издателя показывает актуальное состояние

Частая ошибка: `Forbidden: bot is not a member of the channel chat` — бот Издателя не админ канала
или в `.env` не тот `TG_CHANNEL_ID`.

## 2. Визуал

- [ ] Задача Дизайнеру → в его топике **альбом кадров**, над карточкой у Издателя — те же кадры
- [ ] На слайдах **читаемая кириллица**, а не квадратики
      *(квадратики = не поставлены `fonts-dejavu` / `fonts-noto-core`)*
- [ ] `/рендер <id>` перерисовывает без вызова агента

## 3. Публичная статика

- [ ] `curl -I https://media.домен/…` на любой отрендеренный файл → `200`
- [ ] Ссылка открывается **с телефона по мобильному интернету**, а не только из локальной сети
- [ ] Сертификат настоящий (Let's Encrypt), не самоподписанный

## 4. PDF-лид-магниты

- [ ] `/пдф` в топике Презентатора → три документа пришли в топик
- [ ] В каждом — читаемый текст, число листов совпадает со структурой
- [ ] `/пдф список` показывает три ссылки, каждая открывается в браузере

## 5. Воронка ManyChat

Порядок важен: сначала поля, потом флоу, потом проверка.

- [ ] `/воронка` — три темы, у каждой ссылка и имя bot-поля
- [ ] `/воронка настройка` — карточку скопировали в UI ManyChat
- [ ] В ManyChat созданы 3 bot-поля, собран флоу с 3 кнопками и заведены ключевые слова
- [ ] `/воронка синх` → «Записано полей: 3 из 3»
- [ ] `/воронка тест <ключ>` на каждый из трёх ключей → три **разные** ссылки
- [ ] **С реального аккаунта** написать боту в Instagram-директ ключевое слово → пришла ссылка,
      файл открывается

Помнить: **PDF-файл в директ отправить нельзя**, только ссылку — это ограничение Instagram.
API ManyChat не создаёт флоу, поэтому флоу собирается руками один раз; тариф — **Pro**, на
бесплатном API-ключа не выдают (симптом: 403 при синхронизации).

## 6. Тренды (тратит деньги)

- [ ] `trends/sources.json` заполнен под клиента (аккаунты и хэштеги его ниши)
- [ ] `/тренды` в топике Разведчика → отчёт с темами
- [ ] Повторный `/тренды` в тот же день отказывается — суточный лимит работает
- [ ] `TRENDS_AT` выставлен, если нужен автосбор

Ошибки Apify диспетчер объясняет словами: не принят токен, не найден актор, кончились кредиты.

## 7. Предполётная проверка публикации (делать ПЕРВОЙ, до пп. 8–9)

Одна команда вместо отладки реальными постами. Она **ничего не публикует** — только читает
Graph API и проверяет, видна ли публичная статика снаружи, — поэтому её гоняют сколько угодно раз,
правя `.env` между прогонами.

```bash
cd dispatcher && npm run check:meta
```

То же самое из Telegram: **`/проверка`** в топике Издателя (или словами: «проверь настройки»).

- [ ] Запись в `PUBLIC_DIR` проходит, файл **забирается снаружи по https** → 200
- [ ] Показан аккаунт Instagram — и это **тот самый** аккаунт (`@имя` видно в отчёте)
- [ ] Право на публикацию в Instagram есть, виден остаток суточной квоты
- [ ] Показан аккаунт Threads, и его id **совпадает** с `THREADS_USER_ID`
- [ ] Нет строк «Токены площадок совпадают» / «Id площадок совпадают»
- [ ] Итог: «✅ Instagram: можно публиковать» и «✅ Threads: можно публиковать»

Пока итог не зелёный — переходить к пп. 8–9 бессмысленно: Meta вернёт ту же ошибку, но без
подсказки. Каждая строка отчёта содержит «→ что делать».

Необязательно, но полезно заполнить `META_APP_ID`/`META_APP_SECRET`: тогда проверка назовёт дату
истечения токена. Long-lived токен живёт 60 дней, и «через два месяца всё встало» — почти всегда он.

## 8. Threads

- [ ] `PUBLISH_DRY_RUN=1` → «Одобрить» печатает план вызовов, ничего не публикуя
- [ ] Флаг снят, рестарт → **реальный пост появился в Threads**

Токен от Instagram здесь не работает: у Threads свой API, своё приложение и свой токен — самая
частая ошибка настройки.

## 9. Instagram

- [ ] Сухой прогон карусели прошёл
- [ ] **Карусель опубликована** в аккаунт клиента (2–10 кадров)
- [ ] Подпись на месте *(берётся из `caption`, а не из текста спецификации слайдов)*
- [ ] Reels по готовому `video_url` публикуется *(если видео уже есть)*

Meta App Review не проходим: аккаунт клиента должен быть админом/тестером его же приложения
(dev-mode). Ошибка «не хватает прав» — почти всегда про это.

**Reels публикуется не мгновенно.** Meta забирает ролик по ссылке и обрабатывает его асинхронно;
диспетчер ждёт готовности до 3 минут (`IG_STATUS_ATTEMPTS`), и только потом публикует. Пауза между
«Одобрить» и появлением Reels — это норма, а не зависание. Если ожидание всё же истекло, в топике
будет сказано, **сколько именно ждали**: ролик исправен, достаточно одобрить карточку ещё раз.

## 10. Видео: монтаж на ноуте и приём ролика

Ставится ОТДЕЛЬНО от VPS — на ноутбук клиента (см. [../video/README.md](../video/README.md)).
Порядок: сначала доступ, потом заявка, потом ролик.

- [ ] На ноуте стоит Claude Code (та же Pro-подписка) и все шесть видео-скиллов
- [ ] `ssh pipeline@<vps> 'echo связь есть'` с ноутбука отвечает
- [ ] `video/vps.env` заполнен, `./video/pull-jobs.sh` показывает список (пусть и пустой)
- [ ] «Одобрить» на сценарии Reels → **в топике Видео появилась заявка на монтаж**
- [ ] `./video/upload.sh <файл.mp4> --job <N>` → **карточка ролика в топике Издателя со ссылкой**
- [ ] Ссылка на ролик открывается в браузере (публичная статика, п. 3)
- [ ] «Одобрить» на ролике → **Reels опубликован**
- [ ] «Правка» на ролике отвечает «перемонтируй и залей заново» — так и задумано

Сырое видео через Telegram НЕ носить: Bot API качает файлы до 20 МБ. Ролик тяжелее
`VIDEO_MAX_MB` (300 МБ) приём отклонит — это защита диска, а не сбой.

## 11. Аналитик

- [ ] `/отчёт` в топике Аналитика → пришли факты и выводы
- [ ] `/отчёт 30` считает за другой период
- [ ] `ANALYTICS_AT` выставлен, если нужен еженедельный автоотчёт
- [ ] Метрики площадок: либо `ANALYTICS_INSIGHTS=1` и цифры приходят, либо осознанно выключены

Отчёт работает без единой настройки — по фактам собственной базы. Метрики Instagram/Threads
требуют прав `*_manage_insights`: клиент выдаёт их себе сам в dev-mode. Их отсутствие — не поломка.

## 12. Мозг бренда

- [ ] Клиент заполнил `brand-brain/` (голос, аудитория, продукты, стоп-слова)
- [ ] `brand-brain/08-visual-style.md` заполнен — иначе слайды будут нейтрально-тёмными
- [ ] Перегенерирован один пост «до/после» — разница видна

Поставляется пустым намеренно. **Пока он пустой, контент будет обезличенным — это не брак.**

Если поднят бот **«Мозг бренда»** (T18):

- [ ] Текст в его топике → «✅ Записал», запись появилась в `brand-brain/09-inbox.md`
- [ ] Фото с подписью → файл в `brand-brain/materials/`, строка с подписью во «Входящих»
- [ ] Альбом из 2–3 фото → один ответ на весь альбом
- [ ] `/входящие` → показывает накопленное
- [ ] Задача Сценаристу со ссылкой на идею из «Входящих» → агент её учёл

## 13. Устойчивость

- [ ] `sudo reboot` → после перезагрузки сервис поднялся сам, боты отвечают
- [ ] Бэкап базы снимается (см. [handover.md](handover.md))
- [ ] Бэкап `brand-brain/` снимается — слоты, «Входящие» и файлы клиента живут только там
- [ ] Клиент знает, где смотреть лог: `journalctl -u content-pipeline -f`
