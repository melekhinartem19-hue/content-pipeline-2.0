# Контракт вызова агентов (`agents/`)

Здесь живут агенты контент-конвейера — **по одному самодостаточному markdown-файлу на агента**
(`producer.md`, `scout.md`, `writer.md`, …). Файл читается человеком и Claude Code без нас: всё
поведение агента описано прямо в нём, ничего не спрятано в коде.

| Файл | Агент | Где работает |
|---|---|---|
| [producer.md](producer.md) | Продюсер — раздаёт задачи, держит статус | VPS |
| [scout.md](scout.md) | Разведчик — кластеризует темы из собранного материала | VPS |
| [writer.md](writer.md) | Сценарист — посты, тексты каруселей, сценарии Reels | VPS |
| [designer.md](designer.md) | Дизайнер — спецификации каруселей и обложек | VPS |
| [presenter.md](presenter.md) | Презентатор — структура PDF-лид-магнитов | VPS |
| [publisher.md](publisher.md) | Издатель — предпубликационная проверка | VPS |
| [video.md](video.md) | Видео — монтаж реальных клипов и заливка ролика | **ноут клиента** |
| [analyst.md](analyst.md) | Аналитик — выводы по фактам конвейера | VPS |

**Видео стоит особняком:** это единственный агент с инструментами и файлами — он работает
локальным Claude Code на ноутбуке (монтаж), а не одним проходом `claude -p` на сервере. На VPS
у него есть только бот-нотификатор заявок, который не думает вовсе.

**Бот «Мозг бренда» (T18) — не агент**, поэтому файла здесь у него нет: он не зовёт `claude -p`, а
только складывает идеи и материалы клиента в [../brand-brain/](../brand-brain/) (слот
`09-inbox.md` + папка `materials/`). Все агенты выше читают это сами, вместе с остальным мозгом
бренда. Устройство — [../specs/brand-inbox.md](../specs/brand-inbox.md).

> Реализация контракта — [../dispatcher/src/agent.js](../dispatcher/src/agent.js).
> Подробная спека — [../specs/agent-contract.md](../specs/agent-contract.md).

## Как диспетчер вызывает агента

Диспетчер — «тупая труба». Он НЕ думает: собирает промпт из трёх частей и отдаёт в `claude -p`
(Pro-подписка клиента; прямого Anthropic API нет никогда). Три части промпта:

1. **Роль агента** — содержимое `agents/<key>.md` целиком.
2. **Мозг бренда** — весь `../brand-brain/` (все слоты). Пустые слоты передаются как
   «(слот пуст)» — агент всё равно отработает, но контент будет обезличенным. Это ожидаемо
   до наполнения клиентом.
3. **Задача** — текст, который прислал пользователь.

Промпт подаётся в `claude -p` через stdin (без лимита длины и экранирования).

## Что агент обязан вернуть (унифицированный конверт)

Сначала — готовый к показу результат. Затем на отдельной строке маркер `---META---`, затем
**одна строка** валидного JSON:

```
<готовый пост / карусель / сценарий>
---META---
{ "kind": "tg_post", "status": "draft", "title": "Короткий заголовок" }
```

- `kind` — тип контента. Публикуемые: `tg_post`, `carousel_spec`, `cover_spec`, `reels_script`,
  `reels_video`, `threads_post`. Непубликуемые (в очередь согласования не идут): `producer_plan`,
  `trend_report`, `publish_check`, `pdf_spec`, `analytics_report`. Список — в
  [../dispatcher/src/queue/kinds.js](../dispatcher/src/queue/kinds.js).
- `status` — обычно `draft` (уйдёт в очередь согласования T07).
- `title` — короткий заголовок для списка в очереди.

Диспетчер разбирает конверт (`parseAgentResponse`). Если маркера нет — весь вывод считается
контентом с `kind:"unknown"` (устойчивость к «болтливым» ответам, но агенты обязаны давать конверт).

## Правила оформления агентов (для хендовера)

- **Один файл на агента.** Не прятать определение внутри кода/графа/тикетов.
- Агент **всегда читает brand-brain** перед задачей (это делает диспетчер, подмешивая его в промпт).
- **Финализировать агента только скиллом `/agent-development`** и только в конце сессии, после того
  как поведение согласовано с пользователем. Не гонять скилл по черновику.

## Демонстрационные фикстуры

Учебные заглушки для проверки контракта лежат отдельно и НЕ являются боевыми агентами:
[../dispatcher/test-fixtures/](../dispatcher/test-fixtures/). Все боевые агенты — здесь, в `agents/`.

Цветов в Claude Code шесть, а агентов восемь, поэтому два цвета повторяются: Сценарист и Видео
(создают контент), Издатель и Аналитик (проверяют и объясняют). Это осознанно.
