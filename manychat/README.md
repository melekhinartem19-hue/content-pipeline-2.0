# `manychat/` — инста-воронка: три темы → три PDF

Здесь лежит **конфиг воронки**: три фиксированные темы, по которым Презентатор собирает три
PDF-лид-магнита, и настройки того, как ManyChat отдаёт на них ссылки.

> Секретов в этой папке нет и быть не должно. Ключ/аккаунт ManyChat — только в `dispatcher/.env`.

```bash
cp manychat/funnel.example.json manychat/funnel.json   # и отредактировать под себя
```

Без `funnel.json` сборка честно скажет «воронка не настроена» и ничего не потратит: три вызова
`claude -p` не уйдут в никуда.

## Почему ровно три темы

Матчинг темы в воронке — **три кнопки/ключа, без ИИ-классификации** (правило из `CLAUDE.md`):
дешевле и не мажет. Человек нажимает кнопку или пишет ключевое слово — ManyChat отдаёт ссылку на
соответствующий PDF. Четвёртая тема — это четвёртая кнопка, а не «умное угадывание», поэтому число
тем зафиксировано конфигом, а не решением агента.

## Поля файла

| Поле | Что значит |
|---|---|
| `topics[].key` | латиницей: имя PDF-файла и часть публичной ссылки. **После запуска воронки не менять** — старая ссылка перестанет работать |
| `topics[].title` | название темы: уходит в задачу Презентатору и в текст ответа ManyChat |
| `topics[].keyword` | слово-триггер в директе. Два одинаковых слова у разных тем — ошибка конфига: воронка не поймёт, что отдавать |
| `topics[].button` | подпись кнопки в директе. Пусто = берётся `title`, но у Instagram лимит **20 символов** |
| `topics[].pages` | сколько примерно страниц просить у Презентатора (необязательно; потолок рендера — 12) |
| `topics[].brief` | о чём материал и для кого — это и есть задача агенту. Чем конкретнее, тем меньше воды в PDF |
| `manychat.replyTemplate` | шаблон ответа в директе; подставляются `{title}`, `{url}`, `{keyword}`, `{button}` |
| `manychat.fallbackTelegram` | куда уводить, когда ссылки на PDF нет (тема не собрана или нет публичной статики) |

## Как это работает

```
manychat/funnel.json ──▶ Презентатор (claude -p) ──▶ render/ ──▶ 3 PDF
                                                                  │
                                          Nginx-статика (PUBLIC_DIR) ◀┘
                                                    │
                            3 публичные ссылки ──▶ bot-поля ManyChat: pdf_<ключ>
                                                    │
                             флоу в директе: «Держи материал — {{pdf_content_plan}}»
```

Сборка запускается командой **`/пдф`** в топике Презентатора (или `/пдф <ключ>` для одной темы) —
подробности в [specs/presenter-pdf.md](../specs/presenter-pdf.md).

## Как ссылки попадают в ManyChat (T14)

Диспетчер **записывает** три ссылки в bot-поля ManyChat (`pdf_content_plan`, `pdf_reels_hooks`,
`pdf_sales_posts`) — команда **`/воронка синх`** в топике Презентатора, а после сборки `/пдф` это
происходит само. Флоу с тремя кнопками собирает **человек** в UI ManyChat один раз: API ManyChat
умеет читать и писать поля, но не умеет создавать флоу и кнопки.

Готовую инструкцию с точными именами полей, подписями кнопок и текстами печатает
**`/воронка настройка`** — её остаётся скопировать в ManyChat. Что воронка отдаёт прямо сейчас,
показывает **`/воронка`**, а репетицию ответа — **`/воронка тест план`**.

Ключ API (ManyChat → Settings → API) живёт только в `dispatcher/.env` как `MANYCHAT_TOKEN`; без
него всё остальное работает, ссылки просто вставляются во флоу руками. Подробности —
[../specs/manychat-funnel.md](../specs/manychat-funnel.md).

## Гоча, которую важно знать про PDF в директе

**Файл-PDF в Instagram-директ отправить технически невозможно.** Поэтому воронка отдаёт **ссылку**
на статику (`PUBLIC_BASE_URL`) или уводит в Telegram. Это ограничение площадки, а не недоделка:
никакой настройкой ManyChat превратить ссылку в файл нельзя.
