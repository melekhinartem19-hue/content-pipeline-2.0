# Видео: монтаж на ноуте клиента и приём ролика на VPS (T15 + автомонтаж T16)

Замыкает последний разрыв конвейера: сценарий Reels рождается на VPS, монтаж идёт на ноуте
клиента, а готовый ролик возвращается в ту же очередь согласования и публикуется в Instagram.

> Устройство системы и правила — [../CLAUDE.md](../CLAUDE.md). Инструкция для ноутбука —
> [../video/README.md](../video/README.md). Очередь согласования — [approval-queue.md](approval-queue.md).
> Публикация в IG — [ig-threads-publish.md](ig-threads-publish.md).

## Круг целиком

```
Сценарист         Издатель            видео_jobs         ноут клиента          Издатель        Instagram
   │ сценарий Reels   │ «Одобрить»         │ заявка            │ монтаж             │ «Одобрить»      │
   └────────────────▶ │ ─────────────────▶ │ ◀── pull-jobs.sh ──┤                    │                 │
                      │                    │                   │ upload.sh (scp+ssh) │                 │
                      │                    │ закрыта ◀──────────┴──▶ ingest:video ──▶ карточка ──────▶ Reels
```

Публикуется только то, что владелец одобрил **дважды**: сначала сценарий (отправить в монтаж),
потом готовый ролик (выпустить в ленту). Это не лишний шаг: смонтированное почти никогда не равно
задуманному, и смотреть надо именно видео.

## Решения и почему так

| Решение | Почему |
|---|---|
| Монтаж только на ноуте | Bot API качает файлы до 20 МБ (правило 5) — сырой материал на VPS не попадает физически |
| Доставка по SSH (`scp` + `ssh`), а не вебхуком | Диспетчер не слушает входящих соединений: портов наружу нет — то же решение, что в воронке ManyChat |
| Ролик копируется в `PUBLIC_DIR` | Instagram не принимает файл: Graph API берёт `video_url` и качает ролик сам |
| Заявки забирает ноут (pull) | VPS не знает, включён ли ноут; заявка ждёт в БД, а не теряется сообщением |
| Отдельный вид `reels_video` | `reels_script` — это текст без ролика; их нельзя путать, иначе IG-публикация сорвётся |
| «Правка» на ролике запрещена | На VPS нет ни исходников, ни монтажной — честный отказ лучше пустого вызова `claude -p` |

## Приём ролика: что проверяется до копирования

1. **Публичная статика настроена** (`PUBLIC_DIR` + `PUBLIC_BASE_URL`). Нет — отказ сразу, файл не
   копируется: отдавать ролик всё равно нечем.
2. **Файл существует, это MP4 или MOV** — что принимает Instagram.
3. **Файл не пустой** (недоехавший `scp` виден сразу) **и не тяжелее `VIDEO_MAX_MB`** (300 МБ).

Дальше ролик получает безопасное имя `ГГГГММДД-ЧЧММСС-исходное.mp4` (пробелы и кириллица в URL —
источник битых ссылок у Meta), копируется в `PUBLIC_DIR/<VIDEO_PUBLIC_SUBDIR>/` и встаёт в очередь:

```
platform: ig            kind: reels_video       status: pending
meta: { video_url, caption, source: 'laptop', file, bytes }
```

Подпись живёт в `meta.caption` — Instagram берёт её оттуда, а не из `content` (см. гочу в
CLAUDE.md). В карточке у Издателя появляется строка `🎬 Ролик: <ссылка>`: владелец смотрит видео
до решения, а не после.

## Автомонтаж (T16)

«Автоматически» здесь означает «задача сама доезжает до ноутбука», а не «монтаж без человека»:
клипы выбирает и собирает человек.

- **Заявка создаётся** в момент «Одобрить» на сценарии Reels (`needsMontage` → `createJobFromItem`).
  Повторное нажатие дубля не создаёт.
- **Уведомление** уходит в топик Видео — бот-нотификатор, который сам ничего не думает
  (`agent: null` в реестре: `claude -p` он не зовёт).
- **Ноут забирает** заявки: `./video/pull-jobs.sh` (человеку) или `--json` (локальному Claude Code).
- **Заливка закрывает** заявку: `./video/upload.sh out/reels.mp4 --job 12`.

Команды в топике Видео: `/видео` — список, `/видео 3` — сценарий заявки целиком,
`/видео отмена 3` — снять. Любой другой текст → короткая подсказка (вызова `claude -p` не будет).

## Границы

- **Ноут не обязан быть включён**: VPS работает без него, не работает только видео.
- **Правка ролика кнопкой не работает** — диспетчер отвечает «перемонтируй и залей заново».
- **Сырое видео не ходит через Telegram** ни в одну сторону.
- **Ролик без публичной статики не принимается** — это устройство Graph API, а не недоделка.

## Проверка

- Оффлайн: `npm run smoke` — `smoke-video` (приём, карточка, слот, отказ правки, путь в Reels) и
  `smoke-jobs` (заявки, закрытие роликом, отмена).
- Живьём: только на VPS клиента — нужны публичная статика по HTTPS и его Meta-приложение.
  Репетиция публикации без последствий — `PUBLISH_DRY_RUN=1`.
