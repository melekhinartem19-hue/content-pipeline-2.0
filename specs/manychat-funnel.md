# Spec: инста-воронка в ManyChat — три ключа → три PDF (T14)

Человек пишет в директ ключевое слово (или жмёт одну из трёх кнопок) — ManyChat отвечает **ссылкой
на свой PDF-лид-магнит**. Матчинг темы — ровно три ключа, **без ИИ-классификации** (правило
`CLAUDE.md`): дешевле и не мажет. PDF по этим темам собирает T13, здесь — «последняя миля».

Код: `dispatcher/src/funnel/reply.js` (чистая логика: тексты, имена полей, карточка настройки),
`dispatcher/src/funnel/manychat.js` (клиент API + синхронизация). Конфиг воронки — видимый
`manychat/funnel.json`, ключ ManyChat — только в `.env`.

## Поток

```
manychat/funnel.json  (три темы: key, title, keyword, button)
        │
        ▼  T13: claude -p → render/ → PDF → PUBLIC_DIR
   funnel_pdfs.url = https://<PUBLIC_BASE_URL>/funnel/<key>.pdf
        │
        ▼  T14: POST /fb/page/setBotFieldByName        ← диспетчер, автоматически после «/пдф»
   bot-поле ManyChat  pdf_<key> = <ссылка>
        │
        ▼  флоу в директе (собран человеком в UI один раз)
   кнопка «Контент-план» / слово «план»
        └─▶ «Держи материал по теме «…» — {{pdf_content_plan}}»
```

## Почему push в bot-поля, а не вебхук

Решение владельца (07.09.2026). Рассматривались три пути:

| Путь | Почему не он |
|---|---|
| **Push в bot-поля** ✅ | выбран: входящих портов нет, диспетчер остаётся «тупой трубой», директ работает, даже когда диспетчер лежит — ссылка уже записана в поле |
| Только инструкция, без API | ссылки статичны, но смена `PUBLIC_BASE_URL` требует ручной правки флоу, и галка тикета «ключ ManyChat в `.env`» остаётся незакрытой |
| Входящий вебхук (External Request) | открытый порт + маршрут в Nginx + авторизация эндпоинта, а директ ломается, если диспетчер недоступен |

**Флоу всё равно собирает человек.** API ManyChat умеет читать и писать поля, но **не умеет
создавать флоу, кнопки и триггеры**. Поэтому диспетчер печатает готовую к копированию карточку
настройки (`/воронка настройка`) и держит в полях актуальные ссылки — остальное делается в UI
один раз.

## Команды (топик Презентатора)

| Команда | Что делает |
|---|---|
| `/воронка` | что воронка отдаёт прямо сейчас: тема → ключевое слово → поле ManyChat → ссылка, и когда её записали |
| `/воронка настройка` | пошаговая карточка для UI ManyChat: имена полей, подписи кнопок, тексты ответов, ключевые слова |
| `/воронка синх` | записать ссылки в bot-поля ManyChat (недостающие поля создаются сами) |
| `/воронка тест план` | репетиция: что человек получит в директе по этому ключу. Ключ темы тоже подходит |

Кроме `синх`, всё читается из БД и конфига — ни `claude -p`, ни ManyChat не дёргаются. После
успешной сборки `/пдф` синхронизация запускается **сама**, если задан `MANYCHAT_TOKEN`.

## Конфиг: `manychat/funnel.json`

К полям темы из T13 (`key`, `title`, `brief`, `pages`) воронка добавляет два:

| Поле | Зачем |
|---|---|
| `keyword` | слово-триггер в директе. Два одинаковых слова у разных тем — **ошибка конфига**: ManyChat не поймёт, какой PDF отдавать, и человек молча получит чужой материал |
| `button` | подпись кнопки. Пусто = берётся `title`, но у Instagram подпись кнопки **20 символов**, а названия тем длиннее — про это предупреждает `/воронка` |

Секция `manychat`:

- `replyTemplate` — текст ответа. Подставляются `{title}`, `{url}`, `{keyword}`, `{button}`;
  остальные фигурные скобки остаются как есть.
- `fallbackTelegram` — увод в Telegram. Используется, **когда ссылки на PDF нет**: тема ещё не
  собрана или не настроена публичная статика. Есть ссылка — идёт она.

## Имена bot-полей

Ключ темы → имя поля: `content-plan` → **`pdf_content_plan`** (дефис меняется на подчёркивание,
префикс задаётся `MANYCHAT_FIELD_PREFIX`). **После настройки флоу префикс менять нельзя**: во флоу
останутся ссылки на старые имена, и директ отдаст пустоту вместо ссылки.

## Что помнит база

Миграция `008_funnel_manychat` добавляет к строке темы три колонки: `manychat_field`,
`manychat_url`, `manychat_at`. Это нужно для одной конкретной поломки: клиент сменил
`PUBLIC_BASE_URL`, пересобрал PDF — в базе новая ссылка, а в поле ManyChat **старая**, и люди
получают 404. Расхождение видно в `/воронка` без единого запроса в ManyChat.

## Гочи

- **Файл-PDF в инста-директ отправить технически невозможно** — только ссылку (правило 3
  `CLAUDE.md`). Ни ManyChat, ни сырой API этого не обходят. Значит, публичная статика
  (`PUBLIC_DIR` / `PUBLIC_BASE_URL`) для воронки не «желательна», а обязательна — либо увод в
  Telegram через `fallbackTelegram`.
- **API ManyChat — только на платном тарифе.** На бесплатном ключ не выдаётся, и синхронизация
  вернёт 403 с этим объяснением. Без токена всё остальное работает: карточка настройки печатает
  готовые ссылки, их можно вставить во флоу руками.
- **Путь `/fb/…` историчен.** Приставка осталась от Facebook-времён, эндпоинты одни на все каналы,
  включая Instagram. Если ManyChat сменит схему — правится константа `PATHS` в `manychat.js` и
  `MANYCHAT_API_URL` в `.env`.
- **ManyChat умеет ответить 200 со `status: "error"`.** Это отказ, а не успех: клиент проверяет
  поле `status`, а не только HTTP-код.
- **Тема без ссылки пропускается, а не пишется пустой.** Записать пустое значение в поле — значит
  сломать уже работающий флоу: в директ уйдёт «Держи материал — » без ссылки. Лучше оставить
  прежнюю рабочую ссылку и сказать об этом в отчёте.
- **Ключ темы (`key`) после запуска воронки менять нельзя** — вместе с ним меняются и имя файла,
  и публичная ссылка, и имя bot-поля: разосланные ссылки перестают работать, а флоу указывает на
  несуществующее поле.

## Проверка

```bash
cd dispatcher && npm run smoke     # smoke-manychat: ключи, поля, тексты, синхронизация, расхождение
MANYCHAT_DRY_RUN=1 npm start       # «/воронка синх» напечатает план запросов, никуда не сходив
```

Живьём воронка проверяется **только на аккаунтах клиента**: нужен ManyChat Pro, подключённый
Instagram и публичная статика. Порядок go-live — в `deploy/` (T17); короткая проверка такая:
`/пдф` → `/воронка` (три ссылки на месте) → `/воронка настройка` → собрать флоу в UI →
`/воронка тест <ключ>` на каждый из трёх ключей → написать боту в директ ключевое слово.
