# 08 — Публикация в TG-канал клиента после «ок»

**What to build:** Одобренный в очереди TG-пост (текст + фото) публикуется в Telegram-канал клиента; учитывается слот контент-календаря. Замыкает полный вертикальный срез Фазы 1: тема → черновик → согласование → публикация в TG.

**Blocked by:** 06 — Сценарист; 07 — Очередь согласования + кнопки.

**Status:** done — spec: [../../tg-publish.md](../../tg-publish.md). Оффлайн-прогон зелёный (`npm run smoke`) + **проверено вживую 07.09.2026** в отдельном тестовом канале: `npm run live:t08` опубликовал пост (`message_id=3`, статус `published`), затем полный путь черновик → карточка → «Одобрить» → пост в канале пройден вручную.

- [x] Только одобренный элемент очереди уходит в публикацию — проверка внутри `publishItem`, мимо кнопки не обойти; pending/rejected/needs_edit/superseded/published → `skipped`
- [x] Пост с текстом и фото публикуется в TG-канал клиента — `sendPhoto` с подписью до 1024, иначе фото + текст сообщениями; длинный текст режется по 4096
- [x] Публикация уважает слот контент-календаря/расписания — слот на будущее → `scheduled`, отправляет планировщик (проверка раз в минуту)
- [x] Статус элемента после публикации обновляется — `published` + `published_message_id` + `published_at`; ошибка → `publish_failed` с причиной и возможностью повтора
- [x] Демо: тема → черновик → «Одобрить» → пост появляется в тестовом канале — оффлайн-эквивалент в `smoke-publish.mjs`, живьём за пользователем
- [x] Короткий spec TG-публикации положен в `specs/tg-publish.md`

**Решение по срабатыванию (согласовано с владельцем):** публикуем **сразу по «Одобрить»**; слот не выброшен — он остаётся необязательной отсрочкой для тех элементов, которым его явно задали командой `/слот`.

**Гоча настройки:** бот Издателя должен быть админом канала с правом публикации, иначе `Forbidden: bot is not a member of the channel chat`. Ошибка не теряется — уходит в `publish_error` и в топик Издателя.
