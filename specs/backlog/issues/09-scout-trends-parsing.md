# 09 — Разведчик: сбор трендов из IG/Threads (Apify) + резерв «вариант C»

**What to build:** Диспетчер собирает посты из Instagram и Threads, дедуплицирует их и отдаёт Разведчику на кластеризацию; готовый отчёт с темами уходит в его топик, темы ложатся в БД для Продюсера и Сценариста.

**Blocked by:** 03 — 6 ботов + роутер; 04 — Контракт агента + brand-brain.

**Status:** done (база) — spec: [../../trends-apify.md](../../trends-apify.md). Оффлайн-прогон зелёный (`npm run smoke`: `smoke-trends`). **Живой прогон требует токена Apify клиента** — у нас его нет, порядок живой проверки описан в спеке.

## ⚠ Смена решения (07.09.2026, согласовано с клиентом)

Тикет писался под **вариант C** — логин ОСНОВНЫМ аккаунтом клиента с принятым бан-риском, а Apify
был «горячим резервом». **Клиент согласился платить за Apify → пути поменялись местами:**

| | было | стало |
|---|---|---|
| основной сбор | логин основным аккаунтом (вариант C) | **Apify** (актор ходит в соцсети сам) |
| резерв | Apify | вариант C, **не реализован** |
| бан-риск аккаунта | принят клиентом | **снят** — мы никуда не логинимся |
| прокси, cookie-сессия | обязательны | **не нужны** |
| «1 прогон/день» | страховка от бана | страховка от **счёта за Apify** |

Критерии ниже отмечены по фактически принятому решению.

- [x] Строго 1 прогон/день — лимит `limits.runsPerDay` считается **из БД** (`trend_runs`), перезапуск процесса его не обнуляет; осознанный обход — только руками, `/тренды сейчас`
- [x] ~~Постоянная cookie-сессия, резидентный прокси, человекоподобный темп~~ — **неприменимо на Apify**: логина нет, сессий нет, трафик идёт со стороны Apify. Требование сохранено для резервного варианта C и записано в `providers.js` и спеке
- [x] Сбор IG/Threads → кластеризация тем → отчёт в топик Разведчика — `src/trends/run.js`: источники → актор → нормализация → дедуп → `runAgent('scout')` → отчёт `=== ТЕМА N ===`
- [x] Резервный путь предусмотрен — `TRENDS_PROVIDER=login`: провайдер есть, **кода логина в нём нет**, он прямо отвечает «не реализован» и перечисляет обязательные страховки. Заглушка, которая «как-нибудь логинится», не ставится: цена ошибки — аккаунт клиента
- [x] Секреты только в `.env` — `APIFY_TOKEN`, `APIFY_ACTOR_*`; список аккаунтов и хэштегов (не секрет) — в видимом [trends/sources.json](../../../trends/README.md), в git не коммитится
- [x] Короткий spec + правила страховки положен в `specs/` — [specs/trends-apify.md](../../trends-apify.md) + [trends/README.md](../../../trends/README.md)

**Решение по расширяемости:** ни одно имя поля актора не зашито в код. Вход (`directUrls` vs `urls` vs `startUrls`), ссылки целей и имена полей в выдаче (`caption` vs `postText`, `likesCount` vs `stats.likes`) описаны в `trends/sources.json`. Актор в Apify Store подорожает или сломается — клиент меняет JSON, не код. В смоук-фикстуре нарочно две площадки с разными форматами.

**Решение по деньгам:** дедуп по ссылке (`trend_posts.url UNIQUE`) экономит дважды — уже разобранный пост не уходит Разведчику и не тратит вызов `claude -p`; при сбое агента собранные посты остаются в БД, чтобы не платить Apify за то же самое повторно.

**Гоча:** `clean=true` у датасета Apify убирает часть служебных полей — тогда источник поста (`@аккаунт`/`#хэштег`) определяется по автору или остаётся пустым. На кластеризацию не влияет.

**Что осталось за рамками:** `trend_topics.used` никем не выставляется — связка «тема → задача Сценаристу» это следующий шаг оркестрации, не T09.
