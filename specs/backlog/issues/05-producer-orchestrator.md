# 05 — Продюсер: раздача задач + статус в группе

**What to build:** Агент-Продюсер работает оркестратором в общей форум-группе: принимает запрос, ставит задачу конкретному агенту (постит в его топик), собирает и показывает статус. Это делает группу управляемой из одной точки.

**Blocked by:** 03 — 6 ботов + роутер; 04 — Контракт агента + brand-brain.

**Status:** done (код) — spec: [../../producer-orchestration.md](../../producer-orchestration.md). Оффлайн-прогон зелёный (`npm run smoke`), живая проверка в группе — за пользователем.

- [x] Продюсер принимает задачу в общей группе и адресует её нужному агенту в его топик — `dispatchPlan` + `postToTopic`
- [x] Продюсер отображает статус выданных задач (кто, что, состояние) — `/статус` из таблицы `tasks`, минуя `claude -p`
- [x] Работает через контракт вызова агента (`claude -p`), а не мимо него — и план, и исполнение идут через `runAgent`
- [x] Демо: одна команда Продюсеру → задача появляется в топике целевого агента + виден статус — `scripts/smoke-orchestrator.mjs` (оффлайн, с инъекциями)
- [x] Короткий spec Продюсера положен в `specs/producer-orchestration.md`

**Гоча, определившая архитектуру:** Telegram не доставляет ботам сообщения других ботов — бот-исполнитель не увидит ТЗ, запощенное бот-Продюсером. Поэтому исполнение замыкает сам диспетчер: он вызывает агента-исполнителя внутри процесса (`runAgent`) и постит результат в топик от имени бота этого агента.
