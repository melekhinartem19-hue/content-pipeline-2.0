# Spec: Контракт вызова агента + brand-brain — T04

База, от которой зависят все 7 агентов: как диспетчер зовёт агента через `claude -p`, как агент
читает «мозг бренда», в каком виде возвращает результат.

## Компоненты
| Файл | Роль |
|---|---|
| [../agents/README.md](../agents/README.md) | Человекочитаемый контракт для авторов агентов |
| [../dispatcher/src/agent.js](../dispatcher/src/agent.js) | Реализация: сборка промпта, чтение brand-brain, парсинг ответа |
| [../brand-brain/](../brand-brain/) | Пустой размеченный шаблон (8 слотов), наполняет клиент |
| [../dispatcher/test-fixtures/](../dispatcher/test-fixtures/) | Демо-заглушка агента + заполненный brand-brain для демо |

## Промпт = 3 части
`buildAgentPrompt`: [роль агента `agents/<key>.md`] + [весь `brand-brain/`] + [задача пользователя].
Подаётся в `claude -p` через stdin. Пустые слоты передаются явно как «(слот пуст)» → контент
обезличен (ожидаемо до наполнения клиентом).

## Конверт ответа
```
<готовый к показу результат>
---META---
{ "kind": "tg_post", "status": "draft", "title": "..." }
```
`parseAgentResponse` делит по последнему `---META---`. Нет маркера → весь вывод = контент,
`kind:"unknown"` (устойчивость). `meta` совместим с очередью согласования T07 (kind/status/title).

### Несколько вариантов в одном ответе
Агент может вернуть 2–3 варианта одного контента. Тогда в `content` каждый вариант начинается
со строки-разделителя `=== ВАРИАНТ N: <короткий угол> ===`, а в `meta` есть `"variants": N`.
На этот разделитель будет опираться очередь согласования (T07), раскладывая варианты на кнопки.
Первым его использует Сценарист — [../agents/writer.md](../agents/writer.md).

## Чтение brand-brain
`loadBrandBrain` читает `brand-brain/*.md` кроме `README.md`, склеивает со заголовками файлов,
считает заполненные слоты (комментарии `<!-- -->` и заголовки за содержимое не считаются).
Возвращает `{ text, filled, total }`.

## Нейтральный cwd
`claude -p` запускается в нейтральной папке (`CLAUDE_CWD`, по умолчанию temp), чтобы агент НЕ
подхватывал строительный `CLAUDE.md` репозитория. Всё, что нужно, агент получает из промпта —
он самодостаточен.

## Демо (критерий тикета)
`node scripts/demo-agent-contract.mjs` — один агент, два прогона: пустой vs заполненный
brand-brain → разный результат (обезличенный vs персональный). Проверено на реальном `claude`.
Оффлайн-версия без claude: `node scripts/smoke-agent.mjs`.

## Правило хендовера
Боевые агенты — по одному файлу в `agents/`, финализируются скиллом `/agent-development` в конце
сессии после утверждения поведения. Черновики скиллом не гонять.
