# Spec: Рендер каруселей и обложек (T10)

Превращает **спецификацию Дизайнера** в **готовые PNG** и кладёт их в топик Дизайнера и над
карточкой согласования у Издателя. Это первый визуальный выход конвейера: до T10 Дизайнер только
описывал кадры словами, теперь описание становится картинкой.

Основа для IG-публикаций (T12) и сборки PDF-презентаций (T13): оба возьмут файлы отсюда.

## Чем рендерим и почему не HyperFrames

Слайд — это **вёрстка**, а вёрстку уже умеет браузер. Композиция живёт как обычный HTML/CSS
([render/templates/slide.html](../render/templates/slide.html)), скриншот снимает headless
Chromium через `playwright-core`. Один браузер на всю карусель, одна вкладка, N скриншотов —
восемь слайдов укладываются в пару секунд.

HyperFrames (о нём говорит CLAUDE.md) остаётся инструментом **видео**: он про таймлайны, кадры и
MP4, тянет FFmpeg и на каждый прогон поднимает таймлайн-сессию. Для статичных картинок это
дороже и медленнее без выигрыша. **Решение владельца от 07.09.2026** — статичный визуал делаем
HTML + Chromium, HyperFrames ждёт видео-фазы (T15).

`playwright-core`, а не `playwright`: он не тянет свои сборки браузеров. Браузер модуль находит
сам — кэш playwright, системный Chrome/Chromium, на Windows ещё Edge. Обновление Chrome рендер
не ломает.

## Поток

```
ответ Дизайнера (claude -p)
   → parseDesignSpec: «=== СЛАЙД N ===» → слайды
   → тема из brand-brain/08-visual-style.md
   → HTML по шаблону  → Chromium → PNG
   → альбом в топик Дизайнера (от бота Дизайнера)
   → тот же альбом в топик Издателя (файлы загружаются заново — см. гочу ниже)
   → карточка согласования с кнопками
```

**Порядок не случайный:** картинки встают НАД карточкой, чтобы владелец согласовывал визуал, а не
его словесное описание.

⚠ **`file_id` привязан к боту.** Идентификатор, полученный ботом Дизайнера при загрузке, для бота
Издателя невалиден — Telegram отвечает `Wrong file identifier/HTTP URL specified`. Найдено живым
прогоном 07.09.2026. Поэтому Издатель **загружает файлы заново**, а не пересылает по id; вторая
загрузка дёшева (кадр ~200 КБ). В META `tg_file_ids` сохраняются вместе с `tg_file_ids_bot` —
чьи они, чтобы на этом не подорвались T12/T13.

## Что рендерится

Решает `kind` из META-конверта агента: `carousel_spec` и `cover_spec` — да, остальное проходит
мимо (шаг холостой). Разделители `=== СЛАЙД N ===` и `=== ОБЛОЖКА ===` объявлены неизменными в
[agents/designer.md](../agents/designer.md) именно ради парсера.

| Роль слайда | Кто получает | Как выглядит |
|---|---|---|
| `cover` | первый слайд и одиночная обложка | заголовок во весь кадр, текст-подводка под ним |
| `body` | середина карусели | заголовок скромнее, акцентная черта, вес на тексте |
| `cta` | последний слайд карусели (если их ≥ 3) | кадр залит акцентом — виден в ленте боковым зрением |

Кадр — **1080×1350** (4:5, вертикаль Instagram). Максимум **10** кадров: столько же в карусели
Instagram и в одном media-group Telegram, лишнее честно отбрасывается с пометкой.

Кегль заголовка и текста подбирается по их длине: кадр фиксированный, скролла нет — что не
влезло, то потеряно.

## Фирменный стиль

Цвета, шрифт и подпись приходят из нового слота **[brand-brain/08-visual-style.md](../brand-brain/08-visual-style.md)** —
единственного, который читает не только агент, но и код. Поэтому строки в нём имеют фиксированный
вид:

```
- Фон: #0E0E10
- Текст: #F5F5F0
- Акцент: #C8FF4D
- Шрифт: Inter
- Подпись: @brand
```

Слот пуст (так он и поставляется клиенту) → **нейтральная тёмная тема**, а в топик уходит честная
пометка «фирменный стиль не задан». Это ожидаемо до наполнения, а не поломка.

Цвет текста на акцентной плашке считается по WCAG: берётся тот из чёрного/белого, у кого контраст
больше. Глазомерный порог здесь ошибается — на средних цветах вроде `#7c8cf8` он выбирает белый
(контраст ~3:1) там, где чёрный даёт ~7:1.

## Поле «Визуал» — честная граница

`Визуал:` у Дизайнера — это идея кадра словами («крупный план чашки, акцент на пар»).
**Иллюстрацию по ней никто не рисует**: рендер типографский. Из описания достаётся только
**мотив** — геометрическая подложка (сетка, волна, дуга, столбцы, пятно) по ключевым словам,
чтобы слайды одной карусели не выглядели одинаково. Нет описания — мотив по номеру слайда.

Генерация настоящих иллюстраций (Higgsfield, Figma) в T10 не входит.

## Что уезжает в очередь

После рендера META элемента очереди дополняется:

| Поле | Зачем |
|---|---|
| `images` | абсолютные пути ко всем кадрам — их возьмут IG (T12) и PDF (T13) |
| `photo` | первый кадр; его уже читает `pickPhoto` публикации (T08) |
| `render_dir` | папка прогона |
| `render_note` | человеческая сводка: сколько кадров, задан ли стиль |
| `tg_file_ids` | id загруженных картинок — годятся только для **того же бота** (см. гочу выше) |
| `tg_file_ids_bot` | чьему боту принадлежат эти `file_id` |

В карточке появляется строка `🖼 Картинок: N`, в `/очередь` — метка `🖼N`.

## Правило «рендер не роняет конвейер»

Нет браузера, агент съехал с формата, Telegram отверг картинку — **черновик всё равно встаёт в
очередь**, а причина уходит текстом в топик. Потерять готовый текст из-за неудавшейся картинки
было бы худшим разменом.

## Команда `/рендер <id>`

В топике Дизайнера. Перерисовывает визуал уже стоящего в очереди черновика: спецификация берётся
из БД, **агент повторно не вызывается** — вызов `claude -p` не тратится. Нужна, когда рендер
сорвался по внешней причине (браузер не поднялся, Telegram отверг файл) или после правки
шаблона/фирменного стиля.

## Компоненты

| Файл | Ответственность |
|---|---|
| [render/spec.js](../render/spec.js) | разбор ответа Дизайнера на слайды (чистые функции) |
| [render/theme.js](../render/theme.js) | тема из brand-brain, контраст, стек шрифтов |
| [render/templates/slide.html](../render/templates/slide.html) | **вёрстка кадра — главный файл для правки внешнего вида** |
| [render/html.js](../render/html.js) | подстановка в шаблон, кегли, мотивы, экранирование |
| [render/browser.js](../render/browser.js) | поиск и запуск headless Chromium |
| [render/index.js](../render/index.js) | публичный вход: спецификация → PNG + `slides.json` |
| [dispatcher/src/render/visuals.js](../dispatcher/src/render/visuals.js) | мост в Telegram: альбомы по топикам, META очереди, `/рендер` |

`render/` **ничего не знает про Telegram, БД и `claude -p`** — получает текст, отдаёт файлы.
Поэтому его можно гонять из смоука и с ноутбука, а всё телеграмное живёт в `visuals.js`.

## Что нужно на VPS

```bash
sudo apt-get install -y chromium fonts-dejavu fonts-noto-core   # браузер + кириллица
cd render && npm install                                        # playwright-core
```

Шрифты обязательны: без пакета с кириллицей слайды отрендерятся квадратиками. Шрифт не
скачивается и не встраивается — берётся установленный в системе.

Свой путь к браузеру, если он лежит нестандартно: `RENDER_BROWSER=/полный/путь` в
`dispatcher/.env`. Готовые PNG складываются в `dispatcher/data/renders/<время>-<вид>/`
(в git не коммитятся), переопределяется через `RENDERS_DIR`.

## Крайние случаи

| Ситуация | Поведение |
|---|---|
| агент ответил без разделителей | рендер не запускается, в топик — «рендерить нечего» |
| блок без полей `Заголовок/Текст` | весь текст блока становится телом слайда, кадр не пустой |
| META говорит «обложка», разделителей несколько | верим разделителям — это карусель |
| слайдов больше 10 | лишние отброшены, в подписи сказано сколько |
| один кадр | `sendPhoto`, а не media-group: Telegram принимает альбом только от 2 до 10 |
| картинки шлёт другой бот | загружаем файлы заново — чужой `file_id` Telegram не примет |
| у Дизайнера не задан топик | файлы отрендерены, в ответе — путь к папке |
| браузера нет | внятная ошибка с командами установки, конвейер продолжается |

## Проверка

```bash
cd dispatcher && npm run smoke      # оффлайн: разбор, тема, вёрстка, PNG, альбомы по топикам
cd render && npm run demo           # посмотреть глазами: пример → render/out/*.png
cd dispatcher && npm run live:t10 "сделай карусель про …"   # ⚠ ПИШЕТ В ГРУППУ, тратит claude
```

`smoke-render.mjs` проверяет сам рендер (без браузера блок PNG пропускается с предупреждением),
`smoke-visuals.mjs` — диспетчерскую часть на подставном рендерере. Живой прогон не покрывает два
хопа принципиально: «человек пишет в топик» (бот не слышит бота, проверено в T03) и нажатие
кнопок карточки (callback приходит только от человека, проверено в T07).
