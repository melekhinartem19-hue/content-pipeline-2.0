# План роллаута T03 — 6 ботов + роутер форум-группы (по 1–2 бота за сессию)

**Зачем отдельный файл.** Поднимать все 6 ботов за один заход — это распухший контекст и грязная
сессия. Поэтому T03 разбит на несколько коротких сессий: **каждая сессия = 1–2 бота**. Этот файл —
пошаговая инструкция, по которой любая будущая сессия продолжит с нужного места без нас.

> Первоисточник тикета: [backlog/issues/03-six-bots-forum-router.md](backlog/issues/03-six-bots-forum-router.md).
> Реестр ботов: [../dispatcher/src/bots/registry.js](../dispatcher/src/bots/registry.js).

## Definition of Done (весь T03, достигается на последней сессии)
- 6 токенов + ID общей группы + ID топиков читаются из `.env`.
- Каждый бот постит в назначенный ему топик форум-группы и обслуживает личку 1:1.
- Роутер по (топик/агент) выбирает обработчик; неизвестный источник обрабатывается безопасно.
- Демо: сообщение в топик агента доходит именно до его обработчика.

Промежуточно (после каждой сессии) система остаётся рабочей: `enabledIdentities()` уже поднимает
**только** тех ботов, у кого задан токен, — частичный роллаут ничего не ломает.

## Целевая архитектура T03
- **Одна форум-группа** (супергруппа с включёнными топиками). По топику на агента + общий топик.
- Каждый бот — свой токен, своя личка 1:1. Все 6 ботов состоят в группе **админами**.
- **Роутинг:** входящее из группы имеет `message_thread_id` = id топика. Каждый бот реагирует
  **только на свой топик** (`message_thread_id === его topicId`) и на свою личку; чужие топики
  игнорирует. Так 6 подключений не устраивают дубль-обработку одного сообщения.
- **Продюсер** (оркестратор) дополнительно умеет постить в чужие топики (раздаёт задачи), передавая
  `message_thread_id` целевого топика при отправке.
- Неизвестный источник (не наш топик, не наша личка) — тихо игнорируется/логируется.

## Разовая инфраструктура (делается в ПЕРВОЙ сессии T03)
1. **Форум-группа:** создать супергруппу, включить Topics, создать топик на агента; записать
   `FORUM_GROUP_ID` и `TOPIC_*` в `.env`. Каждому боту — статус админа. У каждого бота в @BotFather
   **отключить privacy mode** (`/setprivacy → Disable`), иначе бот не видит сообщения в топиках.
2. **Роутер:** `dispatcher/src/bots/router.js` — функция `shouldHandle(identity, ctx)`:
   личка → да; группа → `ctx.message.message_thread_id === identity.topicId`; иначе → нет.
3. **index.js:** повесить `shouldHandle` фильтром в обработчике; при ответе в группу передавать
   `message_thread_id` (ответ уходит в тот же топик). Для отправки Продюсером в чужой топик —
   хелпер `postToTopic(botOfProducer, groupId, topicId, text)`.
4. **.env / .env.example:** добавить 6 `BOT_TOKEN_*`, 6 `TOPIC_*`, `FORUM_GROUP_ID`.

## Рецепт одной сессии (повторяемый)
Для каждого из 1–2 агентов сессии:
1. Создать бота в @BotFather → получить токен; отключить privacy; добавить бота в группу админом.
2. В `.env`: вписать `BOT_TOKEN_<AGENT>` и `TOPIC_<AGENT>` (id его топика).
3. В [registry.js](../dispatcher/src/bots/registry.js): раскомментировать/добавить идентичность
   агента (ключ, tokenEnv, agent, topicEnv). **Не раскомментировать всех скопом** — только тех,
   кого поднимаем в этой сессии.
4. Если у агента есть боевое поведение (это отдельные тикеты — T05 Продюсер, T06 Сценарист и т.д.):
   создать `agents/<key>.md` через скилл `/agent-development` в конце сессии, после утверждения.
   Пока файла нет — можно временно `agent:null` (эхо через claude) только чтобы проверить роутинг.
5. **Проверка:** написать в топик агента в группе → отвечает именно он; написать ему в личку →
   отвечает; написать в чужой топик → он молчит.
6. Пауза, показать результат, «ок» → следующая сессия.

## Гочи (Telegram)
- Топики есть только у **супергруппы** с включённой опцией Topics.
- Без отключения privacy mode бот в группе видит только команды/упоминания — роутинг по топикам
  не заработает.
- `message_thread_id` — это и есть id топика; у сообщений из «General» его может не быть.
- Роутер фильтрует **место**, а не человека: в личке он пускает кого угодно. Кто именно вправе
  говорить с ботами — отдельный allowlist `OWNER_IDS` (09.09.2026), он же закрывает кнопки карточек.
  Пустое значение оставлено рабочим: на первом запуске user_id ещё неоткуда взять.
- Один бот может писать в любой топик (через `message_thread_id`) — это использует Продюсер.
